# WSL 开发交接与尚未实现的设计

## 工作边界

后续代码开发在用户自己电脑的 WSL 中进行，GitHub 保存已提交源码；腾讯云服务器负责运行、内容编辑与部署。现有服务器修改本次收拢提交后，不继续在运行环境实现新的文章关联功能。

复用已有字段的明确 bug、样式及文案调整可以按授权直接处理；新增字段、数据库迁移、业务规则、新服务或自动修改已有数据前，先说明具体计划和影响，取得用户批准。不得自动覆盖个人评分、感想、状态或体验日期。

## 已完成并上线

- Astro 静态网站、Nginx HTTPS 与证书自动续期。
- Payload 的 Works、Media、Users，公网 `/admin` 登录与作品管理；保留原账号和数据。
- “体验清单”名称、个人体验日期及添加时间回退、排序和“有感想”组合筛选。
- 作品变更检测与 180 秒静默防抖；成功构建原子发布，失败保留旧站。
- 当前文章仍来自 Git Markdown。文章 frontmatter 的 `works: [条目-slug]` 可以关联作品，草稿不生成公开关联。
- 当前短感受前台最多显示三行；完整文字保存在 Payload。已有文章关联时短感受可点击，另有“相关文章”区域，这是旧实现，尚未按下面的一篇文章交互收敛。

前台代码在 `src/components/library/`、`src/lib/library/`，现有文章结构在 `src/content.config.ts`、`src/content/blog/` 与 `src/pages/post/[...slug].astro`。可复用的运行配置和发布器已归档至 `deploy/server/`；私密配置与数据不随 Git 分发。

## 已讨论、尚未实施：统一使用 Payload 管文章

不再建立另一套在线 CMS。在现有 Payload 中增加普通文章 Posts，与作品共用账号、媒体、API 和发布流程。当前代码只有 Works、Media、Users，没有 Posts，也没有公网文章编辑 API。

正文保存 Markdown 原文，不转换成 Lexical 富文本 JSON 或预渲染 HTML。建议构建时导出临时 `.md` 和 frontmatter，让现有 Astro 内容集合、remark/rehype 插件、主题组件继续渲染。生成文件只是构建中间产物，不能与数据库形成两个可写权威来源。

这一方案仍需开发与验证：原文章迁移、固定链接、日期与语言字段、草稿/发布状态、文章与作品关联、原始 Markdown 完整保留。相对图片路径、文件引用、主题特殊语法以及可能的 MDX/组件导入需单独验证，不能承诺仅保存原文就完全兼容。普通 Markdown 预览容易接入；正式预览应复用 Astro 渲染，避免出现与正式站不同的效果。

## 已确认的作品关联文章交互，尚未实现

- 一个作品最多关联一篇普通文章，不创建独立“笔记”内容类型或专用文章页面。
- 作品编辑页提供关联文章选择框，可选已有文章或新建一篇。
- 新建/编辑区域保持简单：文章标题和 Markdown 源码编辑，允许纯文字；预览方式后续确定。
- 编辑所选文章修改的是文章本身，不复制一份文章到作品里。
- **“显示文字”就是现有短感受，使用同一个概念，不额外增加独立的链接文字字段。**
- 无文章时，卡片对应位置显示灰色短感受。
- 有文章时，同一位置显示蓝色可点击文字，指向那篇文章；短感受未填写时默认使用文章标题，填写后使用短感受。
- 用户希望选择文章时可默认使用文章标题，但不能静默覆盖已有短感受；具体编辑框如何显示默认值/占位文字、用户清空后的行为，实施前需确认。文章标题变化后默认文案是否跟随，也应明确，避免复制标题造成不必要的数据同步。
- 样式复用现有卡片和普通文章页面，不增加另一套笔记样式，不另建一个并列的重复文章链接块。

本阶段只记录设计，未新增关联字段、未修改数据库、未把短感受变成长文，也未迁移文章。现有“有感想”是暂定名称，包含短感受或关联文章，名称仍可讨论。

## 已讨论、尚未实施：AI / MCP

作品新增、修改、资料搜索及媒体上传 API 已由 Payload 提供，但 MCP 工具和 AI 专用授权尚未配置。当前所有登录账号均为管理员；接入 AI 前需设计受限凭据或角色。未来文章 API 随 Posts 接入，但不直接让 AI 操作 SQLite 或服务器任意文件。

文章和作品应进入同一个发布队列，共用防抖与构建锁，避免增加彼此竞争的定时构建服务。目前自动发布器只观察 Works，尚未覆盖文章变动。

## WSL 接手

克隆 `https://github.com/TraceOnSnow/homepage.git`，阅读 AGENTS.md，按根目录 package.json 的 Node 要求及固定 pnpm 安装。Payload 是独立 npm 应用，保留自己的锁文件。首次启动不能拿空数据库冒充生产数据；需要真实数据时，先制定单独的安全副本传输方案，密钥不写入 Git 或聊天。

下一步应先在 WSL 给出 Posts 与单文章关联的字段/迁移方案和交互草图，经确认后实施，测试通过再提交推送，最后给服务器明确部署任务。
