# 作品表格与体验记录

Payload 管理员登录后打开 `/admin/works-table`，或点击后台导航的“作品表格”。页面通过现有标准 Works、Posts 和元数据 REST API 工作，没有第二套数据库、身份或发布器。

## 日常整理

表格包含全部公开、私密和计划中的作品，REST 分页全部读取后每页展示 50 行。可以按名称／别名、类型、状态、未评分、未填写结束时间筛选。名称打开原生作品详情抽屉。默认列为作品、状态、个人评分、开始时间、结束时间、短感受、关联笔记、可见性和保存情况。

评分 0–10，留空表示未评分，0 分不会被当成空。时间支持年份、年月、完整日期，未知留空。开始时间可选，电影等通常只填写结束时间。默认顺序使用最近结束时间，无结束时间按添加时间兜底；公开卡片分别标注结束时间和添加时间，不把开始时间当作完成日期。不精确日期原样显示，不伪造月日，也不跨时区偏移。

表格中的日期对应数组最后一条体验记录；旧的其他记录和 ID 不改变。详情仍可查看多次体验。原体验状态、平台、进度和备注保存在折叠的只读补充记录中。新的进度说明和备注写在作品短感受，不再要求填写重复字段。

## 添加作品

“记录作品”默认已完成，“加入待体验”默认计划中。弹窗搜索外部资料，先选择类型再输入名称；选择结果后创建私密作品，再在表格补充个人记录和公开设置。通过来源与外部 ID 查重，已有记录直接定位。同名但无法确认版本时停止创建，可在手动添加抽屉核对固定链接。来源详情失败时保留基础搜索资料，不编造字段。创建结果不明确时停止自动重试，刷新核对。

## 关联笔记

没有关联时显示“无”。每部作品最多关联一篇 Posts 文章。选择按钮复用 Payload 原生文章列表抽屉；新建和点击标题编辑复用原生文章编辑抽屉，可以写原始 Markdown、保存草稿或主动发布。

文章抽屉保存会先保存文章；表格里的作品关联仍需点击“保存修改”。草稿标明“草稿”，不会自动发布。取消关联不删除文章。短感受有内容时继续显示其内容作为文章链接文字；为空时动态使用文章标题，不把标题写入短感受。

## 保存与兼容

多个单元格修改后统一保存，不因每次键入直接写入。只发送变化字段。保存前读取 `updatedAt`，并用 ID 和原时间戳约束标准批量 PATCH；冲突或失败保留该行输入，其他成功行显示已保存。这是逐行保存，不是整张表的原子事务，也不是跨所有写入者的绝对锁。重新读取一行会先提示放弃该行本地输入。

后台原生详情抽屉会独立保存；如果同一行另有表格修改，提示核对，避免静默覆盖。离开页面前保存输入。公开内容沿用现有 180 秒静默期与构建发布流程，私密作品和文章草稿不会自动公开。

本次日期字段由 Payload `date` 调整为兼容校验的 `text`；SQLite 原有列本身就是 text。数据库适配器保留 Works 原有 SQL 默认值 `planned`，新增时由 Payload 显式写入应用默认值 `completed`，避免仅为默认值重建表。体验记录旧默认值保持兼容。结构生成器与最后一份迁移快照的 SQL 差异必须为空；未新增／删除列、迁移或重写旧行。管理员、密钥、评分、短感受、文章和体验历史不做批量变换。
