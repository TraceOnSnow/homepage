# 作品表格与体验记录

Payload 管理员登录后打开 `/admin/works-table`，或点击后台导航的“作品表格”。页面通过现有标准 Works、Posts 和元数据 REST API 工作，没有第二套数据库、身份或发布器。

## 日常整理

表格读取全部作品的最新草稿及独立发布版本，REST 分页全部读取后每页展示 50 行。可以按名称／别名、类型、状态、未评分、未填写结束时间筛选。名称打开原生作品详情抽屉。默认列为作品、状态、个人评分、开始时间、结束时间、短感受、关联笔记、发布时可见性和草稿与发布。

评分 0–10，留空表示未评分，0 分不会被当成空。时间支持年份、年月、完整日期，未知留空。开始时间可选，电影等通常只填写结束时间。默认顺序使用最近结束时间，无结束时间按添加时间兜底；公开卡片分别标注结束时间和添加时间，不把开始时间当作完成日期。不精确日期原样显示，不伪造月日，也不跨时区偏移。

表格中的日期对应数组最后一条体验记录；旧的其他记录和 ID 不改变。详情仍可查看多次体验。原体验状态、平台、进度和备注保存在折叠的只读补充记录中。新的进度说明和备注写在作品短感受，不再要求填写重复字段。

## 添加作品

“记录作品”默认已完成，“加入待体验”默认计划中。弹窗搜索外部资料，先选择类型再输入名称；选择结果后创建私密草稿，再在表格补充个人记录和发布设置。通过来源与外部 ID 查重（包含最新草稿），已有记录直接定位。同名但无法确认版本时停止创建，可在手动添加抽屉核对固定链接。来源详情失败时保留基础搜索资料，不编造字段。创建结果不明确时停止自动重试，刷新核对。

## 关联笔记

没有关联时显示“无”。每部作品最多关联一篇 Posts 文章。选择按钮复用 Payload 原生文章列表抽屉；新建和点击标题编辑复用原生文章编辑抽屉，可以写原始 Markdown、保存草稿或主动发布。

文章抽屉保存会先保存文章；表格里的作品关联仍需点击“保存草稿”。文章和作品各有独立发布状态，保存或发布作品不会顺带发布文章。草稿标明“草稿”，不会自动发布。取消关联不删除文章。短感受有内容时继续显示其内容作为文章链接文字；为空时动态使用文章标题，不把标题写入短感受。

## 保存与兼容

多个单元格修改后点击“保存草稿”，不因每次键入直接写入。保存使用标准 `draft=true`、`_status: draft`，只发送变化字段；已公开作品继续显示旧发布版本，即使新草稿把可见性改成私密，旧站也不会因此下架。状态显示“草稿”“草稿修改 · 旧版已公开”或“已发布 · 公开／私密”，刷新后仍以实际版本为准。

先保存输入，再使用每行的“发布到网站”或“发布（私密）”。发布使用已保存的最新草稿全部可编辑字段，保留数组行 ID、部分日期与选定可见性；不是只修改发布标记。只有明确发布且可见性为公开时，作品才会显示到网站。“下架”关闭公开版本，但保留当前最新草稿及历史，可以继续编辑或重新发布。发布和下架均不硬删除作品。

保存前读取最新草稿及基表 `updatedAt`，写前再核对最新草稿；草稿保存以最新版本时间戳约束批量 PATCH，发布／下架以基表时间戳约束。写后回读版本状态才报告成功。冲突或失败保留该行输入，其他成功行显示已保存草稿。这是逐行保存，不是整张表的原子事务，也不是跨所有写入者的绝对锁；结果不明时先重新读取核对，不盲目重发。重新读取一行会先提示放弃该行本地输入。

后台原生详情抽屉使用 Payload 草稿／版本与主动发布入口，保存后表格重新读取最新草稿；如果同一行另有表格修改，提示核对，避免静默覆盖。离开页面前保存输入。明确公开发布或下架沿用现有 180 秒静默期与构建发布流程，保存草稿不会自动更新网站。

既有日期字段继续使用兼容校验的 `text`，SQLite 原值、体验记录及部分日期保留。原作品表格的无结构变更结论仅适用于当时的日期兼容更新；本轮原生 Works 草稿／版本**新增迁移**，需要按迁移文档在隔离副本验证、备份后执行。迁移前不能把新版表格接到旧数据库。开发工作树的验证不代表生产已迁移或部署；管理员、密钥、评分、短感受、文章和体验历史不得重导入或批量改写。

## 验证记录（2026-10-21）

普通字段／历史保留测试、UI 标准 REST 请求测试以及使用临时 SQLite 的真实 Payload 集成测试通过。独立生产构建上的 `works-table.spec.ts` 与 `workflow.spec.ts` 两条真实浏览器场景分别通过：覆盖保存私密草稿仍保留旧公开版、主动发布最新内容、冲突保留输入、下架保留最新草稿、重新发布、原生详情／文章抽屉和全部资料提供方表单。外部元数据响应使用 fixture；网站写入只进入一次性测试库，没有迁移或写入生产内容。

复测命令在 `services/payload` 执行：`node --import tsx --test tests/works-table.test.ts tests/integration/works-table.test.ts`；先构建独立测试环境，再执行 `E2E_PRODUCTION=1 npx playwright test tests/e2e/workflow.spec.ts tests/e2e/works-table.spec.ts`。生产模式避免开发编译器在低内存环境长时间阻塞；截图保存在 Git 忽略的 `.cache/workflow-evidence/works-table-preview.png`。
