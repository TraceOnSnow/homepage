# 作品表格与体验记录

Payload 管理员登录后打开 `/admin/works-table`，或点击后台导航的“作品表格”。页面通过现有标准 Works、Posts 和元数据 REST API 工作，没有第二套数据库、身份或发布器。

## 日常整理

表格读取全部作品的最新草稿及独立发布版本，REST 分页全部读取后每页展示 50 行。可以按名称／别名、类型、状态、未评分、未填写结束时间筛选。名称打开原生作品详情抽屉。默认列为作品、状态、个人评分、开始时间、结束时间、短感受、关联笔记、发布时可见性和草稿与发布。

筛选可匹配当前输入，评分 0 属于已评分。原来符合条件、正在修改的行会保留到保存，避免在“未评分”里输入 95 时第一位就让整行消失；保存后按新值判断。“未保存／操作失败”筛选用于集中处理修改，“清除筛选”恢复全部。翻页或筛选隐藏修改时，保存栏显示不在本页的未保存数量，点击可找回这些行；整表保存仍包括其他页。页码同时显示当前记录范围。

手机上每部作品改为带字段标签的卡片，保存操作固定在底部，不需要横向拖动长表格。桌面保存栏随滚动保留，表格和控件有键盘焦点标记。

评分 0–100，100 满分，默认整数步进，85 等同原 8.5；既有更细小数保留。留空表示未评分，0 分不会被当成空。时间支持年份、年月、完整日期，未知留空。开始时间可选，电影等通常只填写结束时间。默认顺序使用最近结束时间，无结束时间按添加时间兜底；公开卡片分别标注结束时间和添加时间，不把开始时间当作完成日期。不精确日期原样显示，不伪造月日，也不跨时区偏移。

表格中的日期对应数组最后一条体验记录；旧的其他记录和 ID 不改变。详情仍可查看多次体验。原体验状态、平台、进度和备注保存在折叠的只读补充记录中。新的进度说明和备注写在作品短感受，不再要求填写重复字段。

## 添加作品

“记录作品”默认已完成，“加入待体验”默认计划中。弹窗搜索外部资料，先选择类型再输入名称；选择结果后创建私密草稿，再在表格补充个人记录和发布设置。通过来源与外部 ID 查重（包含最新草稿），已有记录直接定位。同名但无法确认版本时停止创建，可在手动添加抽屉核对固定链接。来源详情失败时保留基础搜索资料，不编造字段。创建结果不明确时停止自动重试，刷新核对。

## 关联笔记

没有关联时显示“无”。每部作品最多关联一篇 Posts 文章。选择按钮复用 Payload 原生文章列表抽屉；新建和点击标题编辑复用原生文章编辑抽屉，可以写原始 Markdown、保存草稿或主动发布。

文章抽屉保存会先保存文章；表格里的作品关联仍需点击“保存并同步”。文章和作品各有独立发布状态，保存或发布作品不会顺带发布文章。草稿标明“草稿”，不会自动发布。取消关联不删除文章。短感受有内容时继续显示其内容作为文章链接文字；为空时动态使用文章标题，不把标题写入短感受。

## 保存与同步

表格中的单行“保存并同步”、底部“保存全部并同步”和表格内 Ctrl+S／⌘S，都会保存个人字段并发布作品卡片，不需要再逐条点发布。可见性保持所选值：公开作品更新网站，私密作品仍然私密。编辑输入本身仍在当前页面，点击保存才提交；正文文章保持独立发表。

“发布全部作品更新（N）”处理全部已加载页中，已有公开版且最新仍为公开、表格日常字段与公开版不同的作品，不受当前筛选影响。它不首次公开其他作品、不切换私密性，也不顺带发表文章。有未保存输入时先使用“保存全部并同步”，再处理既有已保存的更新。

同一作品若另有标题、封面、资料来源等非表格字段草稿，快捷保存和批量发布会保留它们并提示先到详情核对，不顺带发布这些内容。单行明确发布与原生详情的主动发布仍用于完整草稿；原生详情中的“保存草稿”继续按原义保留草稿。

写入前重新读取最新稿与正式版并核对时间，写后回读字段和状态才报告成功；体验记录新生成的行ID可以保留，既有行ID和历史记录不改。超时等未知结果先只读对账，不自动重复发送。批量操作逐行显示进度与结果，一行失败不丢其他行输入；这不是整表原子事务或跨所有写入者的绝对锁。

失败行保留输入和“查看失败”入口，核对后可单独操作；筛选、翻页不丢输入。离开后台或关闭页面时有未保存提醒，重新读取一行会先确认放弃本地输入。输入不写浏览器持久存储。原生文章／作品抽屉和添加弹窗保留自己的快捷键行为。

发布成功表示正式API已更新。网站沿用180秒内容静默期，随后构建并原子切换；持续编辑会推迟构建，因此页面不会在每次保存后立刻刷新。失败时保持上一版网站，实际是否上线以页面核对为准。

既有日期字段仍为兼容部分日期的`text`。原Works草稿／版本及回收站迁移已经上线；本次保存与批量发布只使用既有标准API，不新增字段、迁移、身份或服务。下方2026-10-21的草稿保存浏览器记录是旧流程历史验证，不代表现在表格主按钮的语义。

## 验证记录（2026-10-21）

普通字段／历史保留测试、UI 标准 REST 请求测试以及使用临时 SQLite 的真实 Payload 集成测试通过。独立生产构建上的 `works-table.spec.ts` 与 `workflow.spec.ts` 两条真实浏览器场景分别通过：覆盖保存私密草稿仍保留旧公开版、主动发布最新内容、冲突保留输入、下架保留最新草稿、重新发布、原生详情／文章抽屉和全部资料提供方表单。外部元数据响应使用 fixture；网站写入只进入一次性测试库，没有迁移或写入生产内容。

复测命令在 `services/payload` 执行：`node --import tsx --test tests/works-table.test.ts tests/integration/works-table.test.ts`；先构建独立测试环境，再执行 `E2E_PRODUCTION=1 npx playwright test tests/e2e/workflow.spec.ts tests/e2e/works-table.spec.ts`。生产模式避免开发编译器在低内存环境长时间阻塞；截图保存在 Git 忽略的 `.cache/workflow-evidence/works-table-preview.png`。

本轮易用性改动的定向 unit／SQLite integration 共10项通过，覆盖当前输入筛选、导航排除项、批量部分失败及原有发布／历史保持。新增 `tests/e2e/works-table-ux.spec.ts` 已在最终生产构建的隔离浏览器通过：首次503原位重读、隐藏修改找回、导航取消及允许、详情防丢、快捷保存、逐行纠错和390px卡片布局。原两条浏览器流程在同一最终构建亦通过。统一复测时在原两条命令末尾加入该文件；实际8767另以只读方式验收，不覆盖现有示例数据。

自定义作品表格使用 `initPageResult` 的permissions、locale与当前用户传给DefaultTemplate，保留原生作品／文章等侧栏入口；不另造导航或扩大读取权限。手机或侧栏收起时，先通过原生菜单按钮展开导航。
