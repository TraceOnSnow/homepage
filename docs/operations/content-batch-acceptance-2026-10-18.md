## 迭代结果

现有客户端增加 `works import FILE [--apply]`，输入是审阅后的作品 JSON 数组，沿用单条创建字段。默认预览，实际执行保留原记录，按来源身份和标题／别名／slug 去重；同名不同来源、无关 slug 占用和不确定写入返回 review。逐项 POST 后读回个人字段和体验日期，不自动覆盖、发布、删除或重发超时写入。完整用法见[内容工具](../content-tools.md)。

它将确定性循环留给普通程序：Agent 批量识别名单、查资料并审阅身份，之后由一次客户端调用完成创建与核对。资料搜索与具体作品身份仍需审阅，不能把搜索第一条、作者名、系列名或任意译本 / 分卷当作确定作品。

验证包括：内容客户端 13 项本地测试（模拟 API），覆盖既有文章 Markdown 编辑、安装后的独立技能、批量预览／分页／重复／冲突／个人字段读回、超时后的查询恢复及无法核实时停止；Biome、技能验证和差异检查通过。对本次 106 个审阅对象执行生产只读预览，仅 2 次 GET，全部识别为 existing，0 次写入。

不提供跨管理员编辑的数据库事务或来源唯一性约束；检查逐项 review 结果。代码通过独立开发分支交付，本轮不切换生产 checkout 或安装的技能，不触发部署。
