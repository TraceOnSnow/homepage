# 个人记录工作流：体验与验收

## 打开入口

在现有远程编辑器的“端口 / Ports”面板转发服务器8766和8767。本机端口保持相同；原来的8766入口可继续使用。

- 历史初稿：[材料收件箱](http://127.0.0.1:8766/?view=done)。
- 网站示例：[作品管理](http://127.0.0.1:8767/admin/works-table)、[公开效果验收页](http://127.0.0.1:8767/acceptance-preview.html)。

网站预览使用新建示例数据库，含3条作品和2篇文章，正式站及原数据库保持现状。示例账号为 `preview@example.test`，密码由当前总览聊天提供。公开效果页读取匿名标准API，不携带管理员身份，每3秒更新；用于观察发布边界，不是正式静态前端的替代品。

## 历史初稿到内容库

1. 在“已生成”查看现有两篇初稿，选一篇，读后点击“导入 Markdown 库”。此操作不调用模型。
2. 看到“已导入”和文件相对路径，在远程编辑器打开 `/home/trace/projects/personal-records-vault` 中对应文件，核对正文。
3. 在正文末尾补一句话并保存；刷新网页和重新打开文件，修改仍应保留。网页继续保留生成时的初稿，后续编辑以库内文件为准。

希望体验AI编辑／版本恢复时，在总览聊天明确指定笔记与修改要求，由AI使用库工具读当前稿、按SHA修改并保存检查点；需要恢复时再明确指定版本。Obsidian及Copilot尚未连接，暂不把远程编辑体验当成本机Obsidian验收。

## 网站保存、发布与下架

1. 登录示例作品管理，另开公开效果验收页；初始只显示一条7分公开作品和一篇公开文章。
2. 把“验收示例：已公开的作品”评分改为9，点击“保存草稿”。管理端显示9，公开页仍应显示7。
3. 点击该作品“发布”，公开页应在3秒左右变为9；点击“下架”，应从公开页消失；再次发布应恢复。
4. 打开作品详情查看版本历史。也可在“文章”中编辑示例草稿，分别体验保存草稿与发布。

这是网站代码的示例验收。真实Markdown库尚未与正式网站开启常驻同步；实际写入测试只发往隔离环境。可在用户选好一篇内容后，由主Agent带着走一遍库内修改、预览站选版发布和撤回。

## 用户需要反馈

优先反馈入库是否顺手、稿件是否保留必要信息、作品属性／正文的分工和保存／发布流程是否符合习惯。自动化回归、字段保持、迁移及隐私检查由开发者负责，不要求用户运行全套测试。

本机接通时再确认设备系统和实际Vault绝对路径；复用已选豆包输入法与Copilot，不重复比较插件。正式网站上线及同步启用仍是后续单独步骤。

## 维护者运行记录

预览在同一网站worktree的 `services/payload` 中，回环8767、已有生产模式构建；`storage/acceptance-preview/` 保存示例SQLite、独立媒体目录、私有运行配置、日志、PID及浏览器报告，全部被Git忽略。`public/acceptance-preview.html` 是本机生成并忽略的只读验收页，不进入正式源码发布。未复制生产数据库、用户或凭据，未调用模型，未新增systemd／开机任务。

浏览器已核验示例登录、7→9保存草稿仍公开7、发布变9、下架消失、再次发布恢复，最终评分恢复为7。无页面错误。此过程只修改示例数据，原8766入口及真实库未写入。

后台预览的当前PID记录在 `storage/acceptance-preview/server.pid`，核验当时PID的cwd、Next进程及8767监听后才发送SIGINT停止；不能复用文档中的旧PID。停止后需再次体验时，在同目录运行 `python3 storage/acceptance-preview/start.py` 前台启动，Ctrl+C停止；保持已有示例数据库和独立运行配置，不重新运行seed覆盖体验结果。当前不是开机自动恢复服务。
