# Payload 文章与单文章关联：已批准方案

依据 `docs/development-handoff.md`，用户已确认本方案及动态标题回退规则。源码实现与验证在 WSL 进行，线上切换单独执行，见 `docs/posts-deployment.md`。

## 目标与界面

在现有 Payload 后台管理普通文章，继续使用 Koharu 的文章页面和 Markdown 渲染。作品最多关联一篇文章；同一篇文章可以被多个作品引用。

作品编辑页保留所有现有字段，只增加以下操作：

```text
短感受       [原有内容，可留空                         ]
             留空时，有关联文章就显示该文章的标题
关联文章     [未关联 / 搜索选择已有文章                 ]
             [新建文章]  [编辑所选文章]
```

优先复用 Payload 原生关联选择器、新建和编辑界面。文章初始界面以标题、Markdown 源码为主；固定链接、日期、语言及发布状态放在常规设置区域。不新建另一套 CMS，也不先实现复杂预览。

推荐确认的显示规则：无关联文章时，短感受显示灰色；有关联且已发布时，显示一个蓝色文章链接，文字为非空短感受，否则为文章标题。标题默认值只用于显示和输入框占位，不写入 `note`。清空短感受后恢复标题回退，改文章标题后回退文案跟随；已有短感受不变。移除原“相关文章”重复链接块，继续最多显示三行。

关联草稿或下架文章时不产生公开链接，非空短感受仍以灰色显示；发布后才变为可点击。关联不自动改变文章或作品的可见性。多个作品引用同一篇文章时，编辑修改文章本身。

## 数据与权限

建议新增 `posts` Collection：

| 字段 | 用途 |
| --- | --- |
| `title` | 标题 |
| `link` | 固定链接，保留现有路径片段；改标题不自动改链接 |
| `locale` | 语言，与现有目录和语言回退保持一致 |
| `markdown` | Markdown 正文原文，纯文本保存，不转换为 Lexical/HTML |
| `publishedAt` | 原文章发布日期，不用导入时间替代 |
| `description`、`tags`、`categories`、封面与其他原生选项 | 映射现有 frontmatter，未识别选项保留，不静默丢弃 |
| 原生草稿/发布状态 | 复用 Payload 版本与草稿机制 |

作品新增可空的 `article` 单值 relationship，指向 `posts`，不增加独立的链接文字字段。保留 `note` 作为短感受，不新增另一份感想数据。

匿名访问只允许读取可公开发布的文章；草稿、版本历史和写入继续需要认证。密码文章及加密块需单独验证访问和导出规则，不能因增加文章 API 暴露原文。AI/MCP、额外角色和服务不在本轮范围。

## 迁移与构建

1. **新增 schema**：目前本地数据库仍有旧富文本 `posts` 表及历史数据。新 Collection 使用独立物理表名，例如 `cms_posts`；迁移不得删除、清空或复用旧文章表，也不改管理员、作品和媒体。生成 SQL 后逐项审查，在临时数据库和旧库副本中验证；不操作服务器数据库。
2. **导入演练**：先用已迁入的 Markdown 文章验证，正文逐字比较；保留链接、时间、语言和原生 frontmatter 的值。导入工具输出清单，遇到链接冲突、无法映射的选项、MDX 或图片依赖就报告并停止相应切换，不覆盖已有文章。原文件保留备份；frontmatter 重建可能改变 YAML 排版，不把它宣称为整文件字节不变。
3. **单一权威来源**：切换后由 Payload 管理文章；原 Git 文件作为历史备份，不再编辑或与数据库合并覆盖。构建前从文章数据生成临时内容目录，沿用 Astro 内容集合与插件；失败不替换旧静态站。生成文件不提交 Git，不放回可手动写作的原目录。
4. **文章关联收敛**：先核查现有 `works` 数组关系。每个作品为零或一个关联时才可自动映射；存在多篇候选时列出冲突，请用户选择，不擅自截取第一篇。新关系确认后不再同时维护两套关联方式。
5. **共用发布器**：扩展现有观察器，同时检测公开文章、作品和关联变化；沿用同一把锁、180 秒防抖、构建与原子切换。不增加另一个 timer。文章下架或删除也要触发更新；合法空集合与 API 失败要区分。

## 验证与交付顺序

- 先完成 schema、访问控制和单值关系，在隔离数据库验证新增、草稿、发布、修改、下架、关系清空、迁移及重启持久化。
- 再验证真实后台操作与 Astro 输出：新建文章 → 关联作品 → 保存/发布 → 普通文章页可读；短感受保留、空白回退、标题变更及草稿不泄漏。
- 对比原 Markdown 特殊语法、图片和 URL；确认搜索、RSS、分类、归档仍由 Koharu 正常生成。
- 最后扩展发布检测并验证失败保留旧站、编辑期间重启静默期及文章/作品共享构建锁。
- 测试通过后提交、推送，并给服务器明确的备份、迁移、部署、验证和回滚任务；不在本机运行生产 timer 或直接变更线上服务。

短感受空白时动态使用文章标题的交互已获用户确认。实施中为密码文章增加了仅供构建读取的 `/api/content/posts`：由 `CONTENT_BUILD_TOKEN` 认证，公开文章 API 不返回受保护正文；令牌不具有写权限。已改为文章/作品共用冻结快照构建，再检查是否有新变更，避免构建期间读取到混合版本。
